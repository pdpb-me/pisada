# Exercise figures: brief for Claude Code

Drafted 14 Oct 2026 in the claude.ai coaching chat. Pedro reviewed and approved the figures there.

## What this adds

Sessions without a video (neck micro-dose, tendon block, heel-raise test) are text only today. This branch adds a **line-drawing figure for each exercise**:
- a **thumbnail on the session card**;
- **tap the thumbnail** to open a near-full-screen sheet with the figure large, the dose, tempo, cues, "don'ts" and setup.

## Decided (don't re-open these)

- **Style B, line figure.** It's drawn in code from one shared rig, so it's not image files.
- **Static frames.** Start → end, or a single frame for holds. No animation.
- **No sound.** No timers, beeps or set counter.
- **Thumbnails + tap-to-enlarge only.** A full "follow mode" is parked.

## Files on this branch

| File | What it is |

| `docs/figures/rig.js` | The rig: joints, forward kinematics, arm IK, the SVG line helpers. Plain JS, no dependencies |

## Implementation (proposed; follow CLAUDE.md, one step at a time with Pedro)

### 1. Data: one column

Add `plan_sessions.exercises text[] not null default '{}'`, holding exercise slugs in display order.

The **catalog lives in code**, not in the database. It's static, it's versioned with the figures, and it doesn't need a table. This replaces the `exercises` table / `items jsonb` idea in the earlier plan.

Then follow the CLAUDE.md schema steps:
- write the migration file;
- `apply_migration`;
- regenerate `database.types.ts`;
- run `get_advisors`;
- **update `docs/COACH.md`**: the `exercises` column takes slugs from the list above, an unknown slug shows nothing, and adding a new exercise needs a code change.

### 2. Port the figure code to `src/exercises/`

- `rig.ts` and `catalog.ts`, typed. **Keep every pose number and prop coordinate exactly as is**, because they're the approved drawings.
- `strip()` keeps returning an SVG string. Render it in an `<ExerciseFigure slug inset? />` component. `dangerouslySetInnerHTML` is fine here, since the string is generated by our own code from constants with no user input. Converting to JSX is optional.
- **Marker ids:** the arrowhead markers use fixed ids (`fig-ah`, `fig-ah-prop`). With several figures on one screen, make them unique per instance (e.g. suffix with `useId()`).
- **Theme tokens:** add to `src/index.css`, for both light and dark:
  `--fig-body: var(--foreground); --fig-accent: var(--primary); --fig-prop: var(--muted-foreground);`
- Joint dots (`.fig-dot`) are hidden on thumbnails and shown in the sheet.

### 3. Session card

- If `session.exercises` is non-empty, show the exercises the way videos are shown now:
  - the first exercise's thumbnail sits in `CardAction`, the same size as `VideoThumbnail` (`w-28`, figure without the inset);
  - each exercise gets a row in `CardContent` with a small thumbnail and its name.
- The tendon block has 3 exercises. Friday's tendon block also has the foot-ritual video, so a card can show both videos and exercises.
- Tapping a thumbnail or a row opens a **shadcn `Drawer`** (bottom sheet, about 90% of screen height). It contains:
  - the figure large **with** its inset;
  - the dose in big type;
  - the tempo;
  - the cues;
  - the don'ts;
  - the setup;
  - the stop rule (test only);
  - a Close button at least 44 px tall.
- The review page's sheet is the reference for content and hierarchy. Use shadcn components and the app's tokens rather than copying its CSS.
- Check at 360 px wide and in dark mode, and look at the moodboard per CLAUDE.md.
